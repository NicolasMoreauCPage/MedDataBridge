Version 2.00

Pour <evenementServeurActe>

  • La balise <intervention> est devenue facultative.

  • pour la balise <acteCCAM>

    • Ajout d'un attribut exonerationCCAM pour la balise <acteCCAM> permettant de gérer les règles d'exonération CCAM ( Type 053 du référentiel CCAM) :

      • 1 = acte pouvant être exonéré par la règle du seuil et exonérant alors la facture,

      • 2 = acte pouvant être exonéré par la règle du seuil mais n’exonérant pas la facture,

      • 3 = acte exonéré par nature et non exonérant pour la facture,

      • 4 = acte exonéré par nature et exonérant toute la facture,

      • 5 = acte ne pouvant pas être exonéré par la règle du seuil,

      • 7 = acte pouvant être exonéré par nature dans le cadre d'un dispositif de prévention.

    • Ajout de la balise <codeActeExtensionPMSI>, extension ATIH pour la CCAM descriptive à usage PMSI (2 chiffres).

  • Ajout d'un attribut interrogation (valeur O/N), indicateur de l'utilisation du message en mode query.

Pour <LPP>

  • Ajout de la balise <identifiantFournisseur> avec un type code17Libelle120, alternative au SIRET (balise <siretFournisseur>),

  • Ajout de date de péremption du dispositif (balise <datePeremption>),

  • Ajout du numéro de série, identifiant unique du numéro de pièce sur 254 caractères alpha numériques (balise <noSerie>),

  • Ajout du numéro de lot, ensemble de pièces cohérentes dans son processus de fabrication, (<noLot>),

  • Ajout d'un code interne <codeInterneLPP>,

  • Elimination du choix entre <codeLPP> et <codeCommercialLPP>,

  • La balise <LPPs> est devenue facultative afin d'être homogène avec <actesCCAM> et <actesNGAP>,

  • Les balises <montantUnitaireAchatTTC>, <montantEcartIndemnisable>, <montantUnitaireFactureTTC> ont changé de type de données en vu d'accepter la valeur 0,

Pour <UCD>

  • Modification du type de donnée pour la balise <noLot>, passage en chaîne alphanumérique de longueur 15,

  • Les balises <montantUnitaireAchatTTC> et <montantUnitaireFactureTTC> sont facultatives

  • Ajout d'un code interne <codeInterneUCD>,

  • Elimination du choix entre <codeUCD> et <codeCommercial>,

  • La balise <UCDs> est devenue facultative,

  • Les balises <montantUnitaireAchatTTC>, <montantEcartIndemnisable>, <montantUnitaireFactureTTC>, <montantMargeRetrocession>, <montantReconstitution> ont changé de type de données en vu d'accepter la valeur 0,

Pour <patient>

  • La balise <identite> fille de la balise <numeroIdentifiantSante> est devenue facultative, elle était liée à la balise <hebergeurDossierMedicalPersonnel>, reliquat de la gestion du précédent DMP,

  • La balise <hebergeurDossierMedicalPersonnel> est supprimée,

Pour <acteur>

  • La balise <code> fille de la balise <identification> change de type de données, elle accepte des valeurs alphanumériques de longueur maximale 17,

Pour le type de données personnePhysique

  • Le nom usuel et les prénoms sont devenus facultatifs

Pour <telephone>

  • Acceptation des numéros avec des caractères +(),

Pour <codePostal>

  • Possibilité de recevoir les codes postaux des pays étranger,

Pour <numeroAdeli>

  • Acceptation en deuxième position des valeurs A,B (ou a,b) pour le département de la Corse,

Divers

  • Ajout des valeurs d'attribut sans accent. Exemple, la valeur « création » pour l'attribut action est aussi présente en valeur « creation »,

  • Révision des pattern de nombre11, nombre13, nombre14. Autorisation des valeurs vides,

  • La balise <extensionTemporaire> permet d'ajouter temporairement des données nécessaires localement avant intégration dans la nouvelle version du schéma, ces extensions sont à utiliser avec parcimonie dans des contextes locaux pour une démarche de gré à gré et lorsque l'éditeur emploie ces extensions au delà d'un contexte local, il est demandé aux auteurs de remonter cette demande au groupe Hprim XML pour qu'elle fasse potentiellement parti de la norme. Ces extensions seront accessibles pour les balises <intervention>, <acteCCAM>, <acteNGAP>, <LPP>, <UCD>,
